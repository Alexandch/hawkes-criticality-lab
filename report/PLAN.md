## 1. Что должно быть завершено

Работа должна отвечать на три вопроса:

1. Как меняются наблюдаемые характеристики потока при приближении коэффициента ветвления к единице?
2. При каких интенсивностях и длинах наблюдения коэффициент ветвления можно достаточно точно оценить?
3. Какое качество дают методы распознавания высокого текущего n и предупреждения о будущем пересечении при контроле ложных тревог?

Основной результат — воспроизводимые измерения и границы применимости методов. Высокая чувствительность предупреждения заранее не считается достигнутой. Результат с истинной историей n остаётся диагностическим ориентиром симуляции.

## 3. Единственное дополнение к методам

Проверяется **причинная динамическая оценка n и его наклона с учётом неопределённости**. Конкретная реализация и небольшая сетка её параметров фиксируются до оценивания на новом holdout. На каждом решении разрешены только наблюдения, доступные к этому моменту; двустороннее сглаживание с будущими данными исключено.

Сравнение должно включать:

- обычный и календарный оконные MLE как исходные ориентиры;
- MAE и смещение текущего n, ошибку наклона, долю отказов и задержку при смене режима;
- постоянно высокий n, стабильный n ниже порога, рост без пересечения, плавные и внезапные пересечения, снижение и внешние изменения фона;
- раздельные цели состояния и предупреждения;
- одинаковые данные и заранее объявленное правило калибровки для сравниваемых вариантов.

Признак curvature SE из прежнего MLE нельзя автоматически считать откалиброванной дисперсией ошибки. Если он используется в фильтре, его связь с фактическими ошибками нужно проверить на обучении и валидации. Для публикуемого интервала n отдельно проверяется покрытие на симуляциях с известным параметром.

После изменения признаков модель детектора обучается заново. Подстановка сглаженного n в старые веса без проверки соответствия обучению не считается корректным сравнением.

Порядок принятия решения:

1. Выбрать настройки на обучении и валидации, сохранив все трудные отрицательные режимы.
2. Проверить, есть ли выигрыш в оценке n без неприемлемого роста задержки.
3. Если переходить к сравнению детекторов, зафиксировать архитектуру, seed, охват калибровки и первичные метрики до нового финального теста.
4. Сохранить итог независимо от знака улучшения. Если выигрыш не подтверждён, это фиксируется в обсуждении и не запускает новый цикл подбора по тому же тесту.

**18 ноября — граница добавления методов в основной текст.** Незавершённый вариант остаётся перспективой работы; его предполагаемые метрики не включаются в результаты. Это не препятствует завершению проекта на уже проверенной основе.

## 4. Доработка существующих экспериментов

Пилот `simulation_v2` содержит 30 повторов на уровень n. Для окончательного рисунка дисперсии, автокорреляции и кластеризации следует получить несколько сотен повторов либо оставить пилот явно обозначенным и обосновать его ограниченную роль. Увеличение числа повторов не является новым подбором нейросетевого детектора.

Средняя стационарная интенсивность сохраняется одинаковой при изменении n. Интервалы для средних по Монте-Карло не называются доверительными интервалами n отдельного потока. Суточная кластерная характеристика не называется размером генеалогического каскада.

## 5. Прикладная часть

Зафиксированы два городских примера — Chicago и New York City за 2024–2025 годы. Измеряется чувствительность оценок к календарной базе и условный log-likelihood на отложенном 2025 году. Источники — прямые городские выгрузки.

Архив CODE за 2020–2021 годы описывается отдельно. Подготовка панели из 17 городов не означает, что все эти города уже прошли одинаковый итоговый анализ. Прямые выгрузки 2024–2025 не называются обновлённым CODE.

Истинный n городских данных неизвестен. Для них не рассчитывается «точность распознавания критичности» по отсутствующим меткам и не заявляется доказанный причинный каскад.
