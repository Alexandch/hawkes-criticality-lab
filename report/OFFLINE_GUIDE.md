# Проверка перед внедрением, которую можно выполнить самостоятельно

Реальный пилот в полиции для R11 не требуется. Выполняются последовательные прогнозы на архиве, новые отложенные проверки и самостоятельное наблюдение публичных выгрузок. Это позволяет проверить программу и часть статистических предположений, но не измеряет эффект применения в настоящей службе.

## Полный сохранённый эксперимент

В PowerShell из корня проекта, без активации окружения:

```powershell
.\.venv\Scripts\python.exe -m critical_processes.offline_experiment
.\.venv\Scripts\python.exe scripts/verify_offline.py
.\.venv\Scripts\python.exe scripts/summarize_offline.py
```

Для законченного опыта первая команда проверяет хеши и возвращает сохранённый результат. Независимая проверка пересчитывает количества из исходных файлов, маски времени, нормировку, выбор эпох, калибровку, журнал прогнозов и таблицы результатов. Код и архивы прежних R1–R10 не заменяются.

Модели обновляются на 1 января 2024/2025/2026 и 1 октября 2026. Каждый месяц оценивается отдельно. Винтаж обучается только на прошлых блоках, валидация и две части калибровки отделены. Цели должны иметь не менее 28 суток для накопления регистраций. Настройки описаны в [протоколе](OFFLINE_PROTOCOL.md).

Данные 2025 — сентября 2026 уже просматривались в R10; они используются для разработки и проверки стабильности, а не выдаются за новый независимый финальный тест. Новый октябрь 2026 рассматривается предварительно: сначала 1–14 октября, затем весь месяц. Его исходы могут измениться при последующих выгрузках.

## Повторить на новом снимке

Исходные городские CSV, NPZ и SQLite в Git не входят. История R10 должна быть загружена по [основной инструкции](RUN_GUIDE.md). Используйте новые каталоги, чтобы не менять опубликованные хеши:

```powershell
.\.venv\Scripts\python.exe scripts/prepare_offline_data.py --history data/raw/spatial_local --centroids data/processed/spatial_local --raw data/raw/offline_local --out data/processed/offline_local
.\.venv\Scripts\python.exe -m critical_processes.offline_experiment --panels data/processed/offline_local --out runs/offline_local
.\.venv\Scripts\python.exe scripts/verify_offline.py --panels data/processed/offline_local --out runs/offline_local
```

Загрузка за новую дату создаёт другой снимок. Октябрь не превращается в независимый тест повторно после подбора модели по уже увиденным октябрьским результатам.

## Журнал фактической доступности

С 10 ноября 2026 начат собственный журнал первых наблюдений публичных строк. Это не восстановление их публикации в 2019–2026. Источник Chicago опрашивается по `updated_on` и уникальному `id`, SF — по `report_datetime` и `row_id`. Из публичных строк не извлекаются адреса или персональные признаки.

Пример самостоятельной повторной загрузки; даты окна и имя каталога изменяются при следующем запуске:

```powershell
.\.venv\Scripts\python.exe scripts/capture_public_observations.py --city chicago --since 2026-11-01 --until 2026-11-11 --out data/raw/observed_new/chicago
.\.venv\Scripts\python.exe scripts/capture_public_observations.py --city san_francisco --since 2026-11-01 --until 2026-11-11 --out data/raw/observed_new/sf
```

Повторные снимки добавляются в `data/processed/public_observations/rows.sqlite`. У каждой строки сохраняются реальные `first_seen`, `last_seen` и хеш содержимого; изменения отражаются отдельно. Начальная выгрузка содержит 4 304 строки Chicago и 568 SF в выбранном окне на момент чтения. Частичное окно не доказывает удаление отсутствующей записи. Окно SF по дате регистрации не ловит все поздние правки старых отчётов. Это ограничения наблюдаемого источника, а не ошибка классификатора.

Для другого подготовленного CSV есть общий интерфейс:

```powershell
.\.venv\Scripts\python.exe -m critical_processes.observation_ledger --csv data/raw/snapshot.csv --id-column row_id --source my_source --observed-at 2026-11-10T20:00:00Z --scope full_selected_scope --ledger runs/observations.sqlite
```

В этой команде время должно соответствовать фактическому получению вашего снимка. Не подставляйте дату происшествия. Для сравнения правок используйте одинаковые поля и уникальный идентификатор строки; набор строк одного дела может различаться при разных фильтрах.

## Что здесь означает «готовность»

Программные проверки, архивная точность и готовность к оперативным решениям имеют разные критерии. R11 сохраняет статус исследовательского прототипа: нет полной истории публикаций, независимой проверки на будущих наблюдениях и измеренного эффекта вмешательства. Низкая MAE не заменяет полноту/precision тревог. Порог 5% FPR среди отрицательных ячеек не означает, что 95% тревог правильные.

Материалы R11 можно защищать как воспроизводимую проверку перед внедрением и честный анализ его ограничений. Отсутствующий институциональный пилот не препятствует завершению этой исследовательской работы.
